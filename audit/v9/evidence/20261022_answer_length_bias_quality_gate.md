# v9選択肢長さの正解手がかり：500問全件再構成QA（2026-10-22）

**結論：GitHub学術監査v9作業稿に明確なテスト技術上の偏りがあり、出版保留を維持。**
正答が選択肢4件中「文字数で最長（同率時は最初）」となる問題が、v8では111/500問（22.2%）、GitHub版v9では**290/500問（58.0%）**となった。後者の選択肢の長さだけを機械的に手掛かりにすると500問中290問で正答を選べることを意味する。選択肢内容の妥当性とは別の編集課題である。

## 検証入力と再現性

- v8問題・選択肢・正答：`audit/v9/ledger.json`（500問、Git blob `798b56ded466b54ee1f3c055ba192dfa7851dc56`）。
- v9変更履歴：`audit/v9/changes.json`（4,323件、Git blob `a07ea1091845d61333f1923cc44c6b1773d652e7`）。このうち`field=options`の**1,740件を順次再生**。置換元の一致失敗：**0件**。
- 同一IDのv8とv9の4肢の長さを再計算。v8 111、v9 290という数値が既存`baseline_machine.json`と`postfix_machine.json`の結果に**完全一致**した。
- 比較指標は`tools/quiz_audit.py`（168–170行）の`max(range(4), key=lambda i: len(option[i])) == answer_index`。同率は選択肢番号の小さいものを先に選ぶ。順位0（他の肢より短くない）も別に記録。
- 問題ID単位データ：`20261022_v9_answer_length_cues_500.csv`。v8/v9の選択肢長、正答、最長該当、増悪の有無、2番目との差を500行収録。**各選択肢の内容や解説の正誤をこの指標だけで決めない。**

## 編集上の優先対策

1. **まず32問**（正答だけが単独最長で、2番目の選択肢より20字以上長い）を差分CSVから抽出し、正答の説明過剰、誤答の過度な短文化、選択肢の粒度の不揃いを点検。語数の合わせ込みではなく必要な条件句・出典指定を保ち、学術的な精度を下げないこと。
2. 次に10字以上差の122問を点検し、必要に応じて出典に基づいた再作問。修正後は「正答が最長」の新件数を再計算。
3. 500問の正誤妥当性は独立に維持。正答を意図的に短くする・誤答に冗長句を付けるだけの機械的操作は禁止。
4. GitHub学術稿とLibrary版の**単一正本への統合時**に選択肢の自然さと学術正確性を両立する。採用はIDごとに原著資料と4肢/4解説を参照して決める。
5. この偏りが小さくなった後でも完成版の500問・500解説・リンク・目次・表示全頁・EPUBCheck・Kindle Previewerを再検査。

## 出版判定

学術台帳の`確認済み=500`は正答・概念の精読結果であり、受験技術上の手がかりがないことまで保証しない。**GitHub版v9の選択肢長偏りは新たに確定した品質改善残件。release_ready=false / KDP公開・改訂アップロード保留。**
