# 問題集の校正手順

誤りは見つけたら必ずここに足していく。出発点は、KDPレビューの「選択肢1に設問文が入り、解答と解説がずれている」という指摘(v2→v3)。以後 v7 まで、同じ型の誤りが何度も別の形で見つかっている。

## 0. 全体の流れ(版を上げるたびにこの順で行う)
1. 機械検査(§1)で構造の誤りを潰す。
2. 統計(§2)で位置・長さの偏りを見る。
3. **全文を通読**して事実と表現を確かめる(§3)。機械検査では事実の誤りは1件も見つからない。v7の誤り59件はすべて通読で見つけた。
4. 修正は記録ファイルに「旧→新」で書き、スクリプトで適用する(§5)。docxを手で直さない。
5. 適用後に機械検査を再実行し、指摘の種類が増えていないこと、正解番号と解説が変わっていないことを確かめる。
6. `修正一覧_*.md` に、直した内容・要確認の文面・未確認の事項を書く。利用者への報告にも未確認の事項を必ず含める。

## 1. 機械検査(必ず最初に)
`python3 tools/quiz_audit.py 本.docx`

| コード | 意味 | 過去に見つかった例 |
|---|---|---|
| S1〜S4 | 選択肢が4つ・設問文の文末・正誤タグの形式 | |
| S3 | 選択肢に設問文が混入 | 設問文が「1.」に入り、選択肢が1つずれた(26問) |
| D1 | 選択肢が1つずれて解説と対応 | 同上。恒等対応より1つずれ対応の類似度が高い |
| D2 | 解説の並びが入れ替わっている疑い | 模擬試験53の解説1と2が入れ替わっていた |
| P1 | (正)の解説が否定文で終わる | 正解番号が間違っていた(応用ケース3問4) |
| S5 | 早見表と解説の正解が不一致 | |
| T1〜T5 | 不可視文字・重複表記・同字連続・既知の誤植・空白 | 「答答」「複号的」「正義文」など |
| V1 | 表記ゆれ(辞書は`VARIANTS`) | 情意/情緒的フィルター、JF標準/スタンダード |
| X1 | 解説が「選択肢N」を参照 | 並べ替えで壊れる |
| A1 | 正解だけ断定語がある(弱い指標、人が確認) | 誤検出が多い |

D2・P1・A1・X1は疑いの検出であり誤検出がある(v7時点の残りはすべて誤検出と確認済み)。該当問を読んで判断する。

## 2. 統計で偏りを見る(検査の最後に出る)
- 正解位置が各25%前後か。v2は1が41%・2が42%・4が2%、模擬試験は全問「1」だった。`tools/shuffle_options.py`で直せる。
- 正解が最長の選択肢の割合(無作為なら25%)。v2は72%。
- **正解の長さ順位の分布**(`正解の長さ順位`)。誤答を正解より少しだけ長くすると、今度は「正解が2番目に長い」が約7割になり別の手がかりになる。最長・2番目・3番目・最短が各25%に近いのが理想。**v7時点でも2番目が58%で、未解決**。直すなら、2番目の問題の一部で誤答の2つ目を正解より長くする、または正解を少し長くする。
- 長さを直す道具:
  - `tools/rewrite_long_keys.py`: 正解を短く、誤答を長くする辞書(正解÷他の最長が1.4超の問題向け)。
  - `tools/r3/`: `batchN.py` に `B = {問題ID: {選択肢番号: 新しい本文}}` を書き、`python3 tools/r3/apply.py 入力.docx 出力.docx` で適用。正解がまだ最長の問題が一覧で出るので `batchNb.py` で追補する。`_h.py` の `R(問題ID, 番号, 旧, 新)` は原文の一部の置換。`batch9_revert.py` の `REVERT` に入れた問題は書き換えを取り消す。
- 守ること:
  - 誤答は**全文を手で書く**。語尾を機械的に継ぎ足すと「であるであり」「ためため」になる(v6で実際に起きて書き直した)。
  - 正解と問題文と解説は変えない。変えたのが誤答だけか、v前の版と照合する(`quiz_audit.audit`で選択肢・解説・設問を比較)。
  - 誤答の足し方は「誤りの主張は変えず、条件や根拠を足す」。足した文が別の意味で正しくならないか読む。
  - 用語を答える問題は、正解にだけ括弧書きの補足があると目立つ。誤答にも同じ形式で補足を付ける。

## 3. 全文通読(事実と表現の検査)
- `python3 tools/dump_text.py 本.docx 出力ディレクトリ` で、章ごとの `dump_<章>.txt`(設問・4選択肢・正解・解説)と `front.txt`(前付け・ケースの前提文・出題範囲対応表・用語集・あとがき)を作る。
- 200行ずつ読み、見つけたらその場で記録ファイルに書く。問題文だけでなく**解説の言い回し**、**ケース問題の前提文**、**前付けの数値(試験時間・問題数)**、**用語集**も読む。
- 1問ずつ次の順で確かめる:
  1. 正解の選択肢は本当に正しいか。「のみ」「常に」「すべて」「必ず」の断定、法条の但書(例: 著作権法第36条は営利なら補償金が必要)の見落とし。
  2. 誤答は**どこが誤りか言えるか**。言えない(正しい記述になっている)なら選択肢2つが両立している。
  3. 例文・会話が、説明している概念の例になっているか(「清算/生産」は同音、「学校へ行く」は誤用でない、「行きて」は「く→いて」の過剰適用ではない)。
  4. 名称・用語・書名・年次は実在し正確か(下表)。
  5. 解説は各選択肢に対応しているか。設問や選択肢を直したら解説も直す。
  6. 欠落: 音の高さ・図表・記号が選択肢から抜けていないか。
- 過去に見つかった誤りの型:

| 型 | 例 |
|---|---|
| 正解が不正確 | 第36条「営利を問わず補償金なし」、くれる「視点は与え手側」、促音「無声子音の前にのみ」 |
| 誤答が正しい | 「持って参りました」を謙譲語Ⅱとする選択肢が正しく、正解と両立 |
| 誤答が別の正解と競合 | 「*食べらない」も過剰般化、単語カードは分類により認知にも記憶にも当たる |
| 実在しない・不正確な名称 | 『敬意の美しい示し方』、「多文化共生推進指針」、「生活上の標準的なCan-do」 |
| 似た別の用語との取り違え | バーンガ/バーガバーガ、混種語/混成語、発話媒介行為/発話後行為 |
| 例文が概念に合わない | 「清算/生産」、借訓仮名の例「山=やま」 |
| 年次・数値 | 国際学友会は1935年、現代仮名遣いは1986年、県名用字の列挙(香・阪・縄は1981年から常用) |
| 前提文の誤り | ケース問題の教師の説明「本人に尊敬語は不自然」が誤り |
| 前付けの数値 | 応用試験の試験時間 |
| 誤植 | 「対行」「走出しそうだ」「においも」「自然な自然な」 |

## 4. 事実確認の方法と限界
- 法令の条番号・年次は一次情報で確認する。v2では日本語教育推進法の条番号が複数誤っていた(基本理念は第3条、国の責務は第4条、地方は第5条)。
- この環境では e-gov・国会・文化庁・文科省・予備校サイトなど多くのドメインにWebFetchで接続できなかった。WebSearch(standard)は日付や名称の裏取りに使えるが、要約は検索語をなぞって返すことがあり、**複数の結果が独立に同じことを言うか**で判断する。一次情報で確認できない事項は「未確認」と記録して報告する。
- 判断に迷う学説の分類(オマリー/オックスフォードで分類が異なるストラテジー、用語の流派差)は、選択肢が両立しないように設問を作り直す。
- 著者や制作体制など、本文中の自己紹介の記述は検証できない。利用者に確認を促す。

## 5. 修正の作法
- 本文の修正は `tools/r4/fixes*.py` に `(メモ, 旧, 新[, 回数])` で書く。`python3 tools/r4/apply_fixes.py 入力.docx 出力.docx` で適用する。旧がXML上でちょうど指定回数でなければ止まるので、書き換え漏れ・二重適用・書式ランをまたぐ文に気づける。
- 旧に長い文を取るときは `dump` の文字列をそのまま使う(段落内で色付きの別ランに分かれている箇所はまたげない)。用語の全面置換は回数を指定する。
- 正誤タグは色付きの別ランなので、入れ替えるときは色も入れ替える(`shuffle_options.py` は対応済み)。
- 作業用の出力は scratchpad に置き、完成版だけをリポジトリ直下に `…_vN_修正版.docx` として置く。`.gitignore` に `__pycache__/` を入れてある。
- LibreOfficeがdocxを開けなかったため表示確認はできない。zipの健全性とXMLの整形式を確かめ、Kindle Previewerでの確認は人に頼む。
- 変更は `修正一覧_*.md` に残す。書き直した文面は「要確認」と書く。
