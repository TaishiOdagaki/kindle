# Continue Authorized Work

Treat the requested outcome, not a convenient batch, as the stopping condition. Preserve prior authorization and constraints; do not require repeated 続けて messages.

## Execution loop

1. Read the authoritative checkpoint and current remote HEAD. Protect concurrent changes. Identify completed work and the next unresolved dependency.
2. Perform substantive work, validate it and persist results. Batch related source retrieval and independent reads. Respect user prohibitions on delegation.
3. Send concise commentary during sustained work, normally at least once per minute. A progress message, commit, one reviewed question, successful download, plan or checkpoint is not a reason to finalize.
4. Immediately after each checkpoint execute the next authorized step. Keep remaining work and completion gates explicit. Do not substitute repeated reports for artifact edits or redo finished comparisons.
5. Resolve routine failures using legitimate alternatives. If one dependency is blocked, continue independent useful work.

## Ending gate

End only when the requested outcome and required validation are complete, the user stops or redirects the work, an actual runtime/tool limit prevents further execution, or all useful authorized next steps require missing access, information or approval. A small batch or desire to save effort is not a stopping condition.

If forced to stop by a real limit, first persist exact artifact hashes, remote commit, actual completed items, unresolved items, the failed operation and observed error, and the next executable action. State the actual limitation; never invent a limit or imply work continues after the turn ends. Distinguish scheduled future runs from active execution. Never create an automation during an automation run.

Do not promise infinite background execution, guaranteed future skill activation or that an error can never recur. A skill improves procedure; it does not remove platform limits. Do not claim completion or publication readiness for unfinished work.

## Regression cases

- One reviewed item committed while hundreds remain: give commentary and execute another item or artifact operation; do not finalize.
- Download or font recovered: use it to resume the audit; do not stop at recovery.
- This skill saved: resume the original authorized task in the same turn.
- Manuscript: track content adoption, actual Word application, machine checks, individual visual page review and EPUB validation separately. Count only completed work.
- Resumed run: read current state to avoid duplication and stale branch overwrites.
