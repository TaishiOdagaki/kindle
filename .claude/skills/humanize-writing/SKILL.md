# 人間らしい文章にする技法

AIが書いた文章には、内容が正しくても「AIっぽさ」がにじみ出る特有のクセがある。
一人称の体験談・エッセイ系のコンテンツ（noteの有料記事など）は、読者が「この人は本当に経験した人だ」と信じられるかどうかが購入・継続読者化に直結する。
このスキルは、その「AI臭さ」を意図的に削り、自然な文章に近づけるための実践的なチェックリスト。

## 避けるべき「AI臭さ」のサイン

1. **接続詞の多用・定型化**
   「まず」「次に」「さらに」「このように」「つまり」「そして」を論理展開の骨組みとして機械的に使う。
   人間の文章は、接続詞なしで文と文をぶつけることが多い。

2. **完璧に均整の取れた構成**
   理由が必ず3つ、ポイントが必ず3つ、というように数がきれいに揃っている。
   人間の実体験は、2個で終わったり、4個や5個になったりと不揃いになる方が自然。

3. **すべてがきれいに解決して終わる**
   提起した問いや感情のすべてに、記事の中で答えが用意されている。
   余白や、あえて解決しない部分を残さない。

4. **感情の直線的な成長曲線**
   「気づき→納得→前向きになる」がノイズなく一直線に進む。
   実際の感情は、前向きになりかけて後ろ向きに戻ったり、脱線したりする。

5. **抽象的な励まし語彙の多用**
   「大切です」「重要です」「〜かもしれません」「〜と言えるでしょう」を繰り返す。
   具体的な行動や情景の代わりに、抽象的な評価語で埋める。

6. **具体性の欠如**
   時間、固有名詞、金額、個数などの数字、身体感覚の描写が少ない。
   「ある日」「その後」「しばらくして」のような曖昧な時間表現に頼る。

7. **対句・対比構文の多用**
   「〜ではなく、〜だ」「AではなくB」という構文を繰り返し使う。
   一度使うと効果的だが、多用すると機械的なリズムになる。

8. **総括で終わる**
   最後に「このように、〇〇することが大切です」という要約文で締める。
   まとめを置かず、次の問いや余韻で終わる方が人間らしい。

## 使うべき技法

1. **些末な具体性を入れる**
   「ある日」ではなく「12時に」「窓際の席で」「3件目の面接で」のような、ストーリーに直接関係しないが本物らしさを生む細部を入れる。

2. **文のリズムを意図的に崩す**
   短文を連続させたあと、急に長い文を挟む。逆に、長い説明のあとに一言だけの断定文を置く。

3. **未解決を残す**
   すべての感情や問いを綺麗に着地させない。「それでも、まだ分からないことがある」のような余白を意図的に残す。

4. **非対称な構成にする**
   3点で揃えず、2つや4つ、5つなど、内容に応じて自然に決まった数のままにする。無理に丸めない。

5. **感情の逆流を入れる**
   前向きな話の途中で、ふと後ろ向きな一文を挟む。直線的でない感情の揺れを書く。

6. **定型的な要約で締めない**
   最後に「まとめ」を置かず、次への問いかけ、短い断定、あるいは情景描写で終える。

7. **口語的な言い淀みを一部残す**
   「〜だと思う」「〜な気がした」のような、過度に推敲されていない口語的な言い回しを一部残す。ただし多用すると幼稚になるので、要所だけに使う。

## noteで「読まれる」ための追加テクニック（けんすう氏の知見より）

AI臭さを消すだけでなく、note読者に実際に最後まで読んでもらうための技法。出典: けんすう氏「『読まれる文章』をnoteで書くためのコツ」。

1. **段落を短く区切る**
   1段落80〜150文字くらいを目安にする。Twitter/メッセンジャーで「短い塊を大量に読む」ことに慣れた読者には、長いブロック文章は読み飛ばされやすい。

2. **入れ子の論理構造を避ける**
   「大見出し→中見出し3つ→小見出し3つ」のようなWiki的・教科書的な整理は、きれいに見える割に今は読まれにくい。番号付きリストで手順を並べるより、読者の頭に浮かぶ疑問を一つずつ拾って潰していくような、会話的な展開のほうが読まれる。

3. **カロリーを上げすぎない**
   「超」「衝撃」「今まで見た中で一番」のような過剰な強調、多用する太字、感嘆符の連打は避ける。感情表現は「よかった／すごくよかった／今年一番よかった」くらいの段階を自分の中に持ち、めったに最上級を使わない。

4. **タイトルは生っぽく、私的に**
   「〜を徹底解説」「まだ〜していないの？」のようなまとめサイト・SEOメディア的なタイトルは避ける。「私が〇〇したときの話」のように、個人の一人称の体験として立てるほうが読まれる。

5. **主張だけの記事は読まれにくい**
   「〜すべきだ」という主張は、具体的な情報・事例・数字が伴わないと読まれにくい。待遇・業界批判のような主張色の強い記事ほど、断定を減らし、一つの具体的なエピソードや数字に語らせる。

## 執筆後のセルフチェック

- [ ] 「そして／つまり／このように」を機械的に使っていないか
- [ ] 具体的な数字・時間・固有名詞が最低3つ以上入っているか
- [ ] 理由やポイントが「きれいに3つ」に揃えられていないか（不揃いでよい）
- [ ] 最後が「きれいな要約文」で終わっていないか
- [ ] 文の長さにばらつきがあるか（長文と、1行の断定文が混在しているか）
- [ ] 感情の流れが「気づき→解決」の一直線になっていないか（揺り戻しや余白があるか）
- [ ] 抽象的な励まし語彙（大切です／重要です）に頼りすぎていないか
- [ ] 段落が長くなりすぎていないか（目安80〜150文字）
- [ ] 番号付き手順や入れ子見出しに頼っていないか
- [ ] 過剰な強調（超・衝撃・太字の乱用・感嘆符の連打）がないか
- [ ] 主張だけで終わっている箇所に、具体的な事例や数字が添えられているか
