# 薫のnote × Japanese Writing Lab — 運用仕様 v0.1
更新: 2026-10-08 / 状態: 実験仕様（自動同期未実装）

## 役割と参照元
- **japanese-writing-lab** (`TaishiOdagaki/japanese-writing-lab`): ジャンル別・横断の文章研究、根拠付き技法、共通執筆スキルの仕様。まず `AGENTS.md`、`shared-writing-skill/SPEC.md` を読む。
- **このkindleリポジトリ**: 薫の人物・テーマ設定、既存原稿、記事企画、編集、Amazon販促、公開後の実測評価。まず `personas/note_account_concept.md`、`.claude/skills/humanize-writing/SKILL.md` を読む。
- 研究所の一般技法を、実証済みであるかのように断言しない。研究所→執筆の技法採用は人間が承認する。リポジトリ間でファイルを無断上書きしない。

## 一記事の制作フロー
1. 人間が主題・主張・読者・実体験の事実を提示。未確認事実は質問し、架空の体験を実話として書かない。
2. 原稿を **職業エッセイ / 日本語論 / 試験実用 / 書籍紹介** 等の主目的で分類し、目的に合う評価基準を選ぶ。ジャンルを混同しない。
3. `humanize-writing` と研究所の採用済み技法を参照して、問い・矛盾・発見・具体場面から導入を設計。タイトルは2〜3案検討。刺激の強さだけで選ばず本文との一致を確認。
4. 草稿→自然さと面白さの二重レビュー→事実確認→本人承認→手動公開。公式対応を確認するまでnote投稿を自動化しない。
5. 公開後7日・28日に利用可能な実測値を記録。同一ジャンル・近い公開後日数で比較し、仮説と反例を記載。
6. 一般化できそうな知見だけを研究所に「昇格候補」として手動還元。実証済みと取り違えない。

## データ管理
- 入力先: `research/note-performance.csv`（記録用テンプレート）と `research/observations.md`。
- 記録項目: 記事ID・URL・公開日・計測日・計測窓・分類・表示回数・PV・スキ・根拠・仮説・販売施策。
- 表示回数／PV は厳密なCTRではない。累積値と期間値を混在させない。PVが購入や既読完了を意味するともみなさない。
- 売上・KENP・無料ダウンロードは別に記録。因果関係ではなく相関・時期の一致として扱う。
- 2026-10-08のスクリーンショットに見える集計（28日間: 12,541 impressions、525 PV、138 スキ、29投稿）は**会話中の画面目視情報**であり、記事別の数字や公開日、集計定義の検証ができるまで自動で正解データにしない。

## 出版と販促
- 2026-10-10〜11に Kindle 2タイトルの無料キャンペーンを予定とのユーザー報告。日本時間表示とKDP側の実施時刻の差に注意し、設定・公開価格を確認する。
- ガイド ASIN B0H7CCJ8MZ: https://www.amazon.co.jp/dp/B0H7CCJ8MZ
- 完全対策テキスト ASIN B0GX2TDJ7H: https://www.amazon.co.jp/dp/B0GX2TDJ7H
- 無料キャンペーンの結果だけで有料売上増加を断定しない。無料入手と購入を分離する。
- 試験制度・日程・商品仕様・KDP規約は掲載前に一次資料で確認。実際の収録内容を未確認のまま具体化しない。

## 倫理と信頼
- 薫の既存ペルソナと、実在する筆者の経歴・体験を混同しない。「15年の教員経験」「昨年合格」等は設定ファイル上の記述であり、事実確認なしに実体験として宣伝しない。
- 合成した場面・仮想事例は必要に応じ明示。学生や同僚を識別できる情報を保護。
- 反応の強い見出しでも本文にない被害や失敗を大げさに主張しない。
- 既存の原稿、HTML、人物設定、スキルはこの導入で変更しない。
